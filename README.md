# Biplane Game

Лабораторна робота 4: «Node.js: EventEmitter, streams, WebSocket-сервер».

Браузерна гра: пастельний біплан, яким літаєш по арені на canvas.
- [lab-01](https://github.com/Sol777xxx/biplane-game/tree/lab-01): ігровий цикл, фіксований крок, експерименти з event loop.
- [lab-02](https://github.com/Sol777xxx/biplane-game/tree/lab-02): сутності, `World` на `Map`, колізії, кулі, композиція поведінок.
- [lab-03](https://github.com/Sol777xxx/biplane-game/tree/lab-03): Асинхронний JavaScript: Promises, async/await і екран завантаження.

## Запуск

```
npm install
npm run dev          # клієнт (Vite), http://localhost:5173/
npm run dev:server   # сервер (Node), http://localhost:3000/
npm test             # тести клієнта й сервера
```

Потрібен Node.js 24 (див. `.nvmrc`). Гра: `http://localhost:5173/`.
Перевірка коду: `npx biome check .` · тести: `npm test` · порівняння sequential/concurrent: `npm run timing` · головоломки: `npm run puzzles`.

## Керування

| Клавіша | Дія |
|---|---|
| ← → ↑ ↓ або WASD | рух |
| Пробіл | стрільба |
| H | показати або сховати HUD |
| P | вимірювання (лаба 1): 5 с польоту вправо, результат у консолі |

Героя в кабіні обирають на панелі справа вгорі. Адреса з `?debug` відкриває `window.game` і `window.assets` у консолі та показує хітбокси.

Параметри адреси лаби 3: `?latency=300` (затримка на кожен файл), `?seq` (завантажувати по черзі), `?chaos=…` (навмисні збої, див. галерею), `?delay=5000` (затримка відповіді лобі), `?bake` (зберегти спрайтшит).

## Правила гри

- Хмарки дрейфують і відбиваються від країв; наліт на хмарку знімає 35 HP і знищує її.
- Кулі шкодять хмаркам (знищується за 2–3 влучання, очки = радіус) і кораблям. Біплан, вилетівши за край арени, з'являється з протилежного боку, а куля за межею зникає.
- Над збитою хмаркою спливає «+N» (скільки очок додано).
- Знищений біплан вибухає й відроджується через 2 с у безпечній точці зі щитом на 2 с.
- Pickup'и (зірки): **S** щит, **R** швидкострільність, **H** самонавідні кулі. Частина хмарок наводиться на біплан.
- Параметри арени залежать від кімнати, обраної в лобі (див. розділ «Лобі»).

## Потік запуску

```
loading → лобі → гра
```
1. **loading**: `manifest.json` (через `withRetry`) → `loadAll` вантажить спрайти, звуки й `arena.json` паралельно; прогрес-бар рахує готові файли.
2. **лобі**: `GET /api/rooms`, гравець вводить ім'я й обирає кімнату.
3. **гра**: клік по Join це жест гравця, тож саме там розблоковується `AudioContext`, і перший постріл уже зі звуком.

Конфіг арени збирається шарами: значення за замовчуванням ← `arena.json` ← `arena` вибраної кімнати
(`resolveArena` у `sim/game.js`, значення обмежуються діапазонами, сміття ігнорується).

## Шина подій і HUD

`world.bus` це `EventTarget`, єдиний канал від симуляції до решти. Сим кидає `CustomEvent`, не знаючи, хто слухає:

| Подія | Коли | Хто слухає |
|---|---|---|
| `fired` | постріл | audio |
| `hit` | куля влучила | audio |
| `exploded` | знищено хмарку або літак | audio |
| `crash` | хмарка врізалась у літак | audio |
| `pickup` | підібрано зірку | audio |
| `respawned` | літак відродився | audio |
| `scored` | збито хмарку, `{ delta, total, at }` | hud (спливаюче «+N») |

`audio.js` і `hud.js` самі підписуються на шину; `test/bus.test.mjs` перевіряє, що файли в `src/sim/` не імпортують audio і hud.
Новий підписник (лічильник, тряска екрана) додається без змін у сімі.

`AudioContext` створюється на старті, щоб `decodeAudioData` декодував звуки ще на екрані завантаження, а не під час першого пострілу.
Запускається контекст лише після жесту гравця (політика автозапуску браузерів).


## Лобі

`Lobby extends EventTarget` (`src/lobby.js`) не знає про DOM: раз на 3 с робить `GET /api/rooms`
і кидає події `rooms` / `error` / `join`. DOM лобі окремо, в `src/ui/lobbyView.js`.

- Кожен запит має `AbortSignal.timeout` (2 с) і власний `AbortController`.
- Наступний запит планується після завершення попереднього (а не `setInterval`), тож запити не накладаються.
- Щойно гравець натиснув Join (або вкладка стала фоновою), `stop()` обриває запит, що ще летить, і нових не буде.
- `join(name, roomId)` перевіряє ім'я, існування кімнати й що вона не заповнена, зупиняє опитування й кидає `join`.
- Ім'я запам'ятовується в `localStorage`.

Кімнати лежать у `public/api/rooms.json` (dev-middleware Vite віддає їх за `/api/rooms`, лаба 4 замінить це справжнім сервером):

| Кімната | Хмарок | Зірка кожні, с | Самонаведення | Швидкість | Нова хмарка через, с |
|---|---|---|---|---|---|
| Тиха гавань | 3 | 8 | 0 | 1 | 3 |
| Класика | 5 | 8 | 0,3 | 1 | 2 |
| Грозовий фронт | 8 | 10 | 0,6 | 1,3 | 0,6 |
| Переповнена | 5 | 8 | 0,3 | 1 | 2 (місць немає) |

Перевірка таймауту: `?delay=5000` у адресі гри затримує відповідь лобі, і через 2 с видно повідомлення про час очікування.

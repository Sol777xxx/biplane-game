# Biplane Game

Лабораторна робота 3: «Асинхронний JavaScript: Promises, async/await і екран завантаження».

Браузерна гра: пастельний біплан, яким літаєш по арені на canvas.
- [lab-01](https://github.com/Sol777xxx/biplane-game/tree/lab-01): ігровий цикл, фіксований крок, експерименти з event loop.
- [lab-02](https://github.com/Sol777xxx/biplane-game/tree/lab-02): сутності, `World` на `Map`, колізії, кулі, композиція поведінок.

## Запуск

```
npm install
npm run dev
```

Потрібен Node.js 24 (див. `.nvmrc`). Гра: `http://localhost:5173/`.
Перевірка коду: `npx biome check .` 

## Керування

| Клавіша | Дія |
|---|---|
| ← → ↑ ↓ або WASD | рух |
| Пробіл | стрільба |
| H | показати або сховати HUD |
| P | вимірювання (лаба 1): 5 с польоту вправо, результат у консолі |

Героя в кабіні обирають на панелі справа вгорі. Адреса з `?debug` відкриває `window.game` у консолі та показує хітбокси.

## Правила гри

- Хмарки дрейфують і відбиваються від країв; наліт на хмарку знімає 35 HP і знищує її.
- Кулі шкодять хмаркам (знищується за 2–3 влучання, очки = радіус) і кораблям. Біплан, вилетівши за край арени, з'являється з протилежного боку, а куля за межею зникає.
- Знищений біплан вибухає й відроджується через 2 с у безпечній точці зі щитом на 2 с.
- Pickup'и (зірки): **S** щит, **R** швидкострільність, **H** самонавідні кулі. Частина хмарок наводиться на біплан (закоментоване пунктирне кільце для демонстрації).

## Архітектура

```
demo/
  this-bug.mjs   відтворення і фікс бага з this
src/
  loop.js      ігровий цикл (rAF + акумулятор)
  input.js     клавіатура як замикання
  main.js      збірка та HUD
  sim/         модель світу без DOM:
    vector.js    Vector2 (чисті методи)
    entity.js    базовий Entity, #id, behaviors, краї арени
    biplane.js   Biplane extends Entity, #hp, fire()
    objects.js   Bullet, Obstacle, Explosion, Pickup, createParticle
    behaviors.js homing, lifetime, drag, pickup (композиція)
    world.js     Map<id, Entity>, spawn/despawn/sweep, ofKind
    collision.js коло-коло, окрема система
    game.js      правила: рахунок, респаун, pickup'и
  render/      малювання на canvas
  ui/          панель вибору героя
```

Успадкування лише на один рівень: `Biplane`, `Bullet`, `Obstacle`, `Explosion`, `Pickup` розширюють `Entity`.
Частинки окремого класу не мають: це `Entity` з поведінками `lifetime` і `drag`.

## Потік запуску

loading (манифест, спрайти, звуки, `arena.json`) → лобі (`GET /api/rooms`, ім'я й кімната) → гра.
Конфіг арени збирається шарами: значення за замовчуванням ← `arena.json` ← `arena` вибраної кімнати
(`resolveArena` у `sim/game.js`, значення обмежуються діапазонами). Параметри: `obstacles`, `pickupEvery`,
`homingChance`, `speed`. Клік по Join це жест гравця, тож саме там розблоковується AudioContext.

## Sequential `await` vs `Promise.all`

`npm run timing`: 8 файлів, на сервері штучна затримка 250 мс на кожен, три прогони.

| Режим | Прогони, мс | Середнє |
|---|---|---|
| sequential (`await` у циклі) | 2045, 2023, 2011 | 2026 мс |
| concurrent (`Promise.all`) | 258, 257, 255 | 257 мс |

Різниця ×7,9: sequential це сума затримок (8 × 250), concurrent це максимум (≈ 250 + накладні витрати).

У браузері: `/?latency=300` проти `/?latency=300&seq`, час у рядку `assets [...]` у консолі.

## Спрайтшит

Кораблі, кулі, pickup-зірки й хмарки малюються з атласу `public/assets/sprites.png` + `sprites.json`
(завантажується через loadAll як `image` і `json`). Атлас згенерований тими самими draw-функціями:
відкрийте гру з `?bake`, і браузер завантажить обидва файли. Якщо файлів немає (404), `initSprites`
запікає такий самий атлас у пам'яті, тож гра стартує, а екран завантаження показує попередження.
Блискавки, щит, частинки й вибухи динамічні, тому лишаються процедурними.

## HUD і шина подій

`world.bus` (EventTarget) єдиний канал від симуляції до решти: `audio.js` слухає `fired`, `hit`, `exploded`,
а `hud.js` слухає `scored` і малює спливаючі «+N» над місцем знищення хмарки. Сим не імпортує ні audio, ні hud,
це перевіряє `test/bus.test.mjs`. Додати новий підписник (лічильник, тряска екрана) можна, не чіпаючи sim.

## Лобі

`Lobby extends EventTarget` (`src/lobby.js`) не знає про DOM: раз на 3 с робить `GET /api/rooms`
і кидає події `rooms` / `error` / `join`. Кожен запит має `AbortSignal.timeout` (2 с) і власний
`AbortController`. Наступний запит планується після завершення попереднього, тож вони не накладаються.
Щойно гравець натиснув Join (або вкладка стала фоновою), `stop()` обриває запит, що ще летить, і нових не буде.
DOM лобі окремо в `src/ui/lobbyView.js`: усі слухачі підписані з одним `signal`, тож `abort()` знімає їх разом.
Перевірка: `?delay=5000` у адресі гри затримує відповідь лобі, і видно повідомлення про таймаут.
